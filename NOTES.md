# Решения и замеры

## Где что хранится (проверено на реальных данных, 2026-10-05)

- **Облако Riot** (`Ares.PlayerSettings`): бинды, чувствительность, прицел, миникарта, статистика на экране,
  звук, кровь и т. п. Формат — base64(raw deflate(JSON)). Хранятся **только отличия от стандарта**.
  - Чтение/запись: `https://player-preferences-usw2.pp.sgp.pvp.net/playerPref/v3/{getPreference/Ares.PlayerSettings | savePreference}`.
    Старый адрес `playerpreferences.riotgames.com` перестал отвечать (обрыв TLS) — актуальный берём из `ShooterGame.log`.
  - Токены — из локального клиента: `lockfile` → `https://127.0.0.1:{port}/entitlements/v1/token` (Basic riot:{password}).
- **Графика** — только локально, у каждого аккаунта своя папка `%LOCALAPPDATA%\VALORANT\Saved\Config\<puuid>-<регион>\`:
  `WindowsClient\GameUserSettings.ini` (разрешение, режим, letterbox, VSync) и графические ключи
  `Windows\RiotUserSettings.ini` (лимит FPS, Reflex, качество, AA, анизотропия, чёткость).
  Ключи статистики `PlayerPerfShow*` с заглавной R — облачные, не графика (поэтому regex с учётом регистра).
- Игра читает облако при старте и перезаписывает локальную графику при выходе → применять до запуска / при закрытой игре.
- **Проверено логером 2026-10-05**: `RiotUserSettings.ini` игра пишет **сразу** после смены графики (при запущенной игре,
  ~через секунды) → снимок графики («Сохранить эталон») при идущей игре актуален. Писать в файлы при идущей игре нельзя:
  игра держит значения в памяти и перепишет их при следующем сохранении.
- Файл тоже хранит **только отличия от стандарта**. Качество (проверено в игре): низкое = `0`; среднее = `1` (UI/Detail/Texture), но `MaterialQuality` = `2`; высокое = стандарт, ключа нет.
- При старте игра копирует разрешение аккаунта в общий `Config\WindowsClient\GameUserSettings.ini` (не по аккаунту — не трогаем).
- У одного PUUID бывает несколько папок регионов (`-eu`, `-ap`) — графику писать во все.

## Решения

- **Узкий инструмент** (2026-10-10): задача — «мои настройки на любом аккаунте, где я играю; аккаунту — его исходные».
  Убрано то, что её не решает: редактор «Изменить» (настройки меняют в игре, VALSET их запоминает), наборы
  (сценария не нашлось), код для друга (другая задача и требует VALSET у получателя). Главный экран — только
  нужное сейчас, остальное — «Ещё». Не добавлять: портативный режим, синхронизацию графики между ПК, запуск игры
  через VALSET, профили под агента/роль. Описание настроек (schema.ps1) осталось только для подписей предпросмотра.
- **Интерфейс — с точки зрения игрока** (2026-10-06): «мои настройки» вместо «эталон», «Запомнить как мои» / «Перенести мои».
  Главный экран отвечает на «какой аккаунт, мои ли на нём настройки, что нажать»: сверка с облаком при каждом
  открытии (~0,5 с), курсор на рекомендуемом действии. Аккаунты — по Riot ID (`/player-account/aliases/v1/active`
  локального клиента), реестр в `accounts.json`.
- **Помощник — только по выбору** (2026-10-06): фоновый процесс пугает как слежка, поэтому по умолчанию выключен,
  `config.json` { notify: false, autoApply: false }; install включает его, только если человек включил раньше.
  Уведомления (Windows toast от имени PowerShell, AppId `{1AC14E77-…}\WindowsPowerShell\v1.0\powershell.exe`;
  типы WinRT `ToastNotificationManager` и `Windows.Data.Xml.Dom.XmlDocument` грузить явно):
  чужой аккаунт — «не твои (N)»; основной — при входе и после каждой игры (сторож ждёт 20 с после выхода),
  один раз на каждое новое расхождение (отпечаток отличий в accounts.json → `notified`).
- **Помощник без опроса** (2026-10-06): сторож `valset-agent-3.exe` ничего не перебирает по таймеру.
  Клиент закрыт — ждёт `lockfile` через FileSystemWatcher; клиент открыт — слушает его WAMP-канал (`OnJsonApiEvent`).
  Проверено на живом клиенте: вход — `Create /entitlements/v1/token` (несколько подряд → пауза 15 с),
  запуск игры — `Create /product-session/v1/external-sessions/<id>`, закрытие — `Delete …/<id>` (через 20 с — проверка
  основного); выход из аккаунта тоже удаляет сессии → проверка после игры только если видели её запуск.
  Процесс игры не трогаем (Vanguard). Замер: 0 мс процессора за 10 с простоя, Диспетчер задач — 4,6 МБ
  (EmptyWorkingSet в ожидании; собственная память ~22 МБ — библиотеки WebSocket).
- **Автоперенос без ярлыков**: сторож (C#; v2 опрашивал процессы раз в 3 с — заменён на v3 без опроса; ~15 МБ памяти, автозапуск через HKCU Run)
  раз в 3 с: клиент открыт, игры нет, слежения нет → `valset watch` скрыто. Вход (pid клиента + PUUID) обрабатывается
  один раз (`watch-done.txt`). **Основной аккаунт не трогается** — иначе откатывал бы настройки, изменённые в игре.
  Старый ярлык «VALORANT (VALSET)» и `launch` убраны (install удаляет ярлык).

- **Мои настройки меняются только явно**: «Запомнить как мои» или возврат из истории. Автоматика только применяет.
- **Слежение** живёт от открытия клиента до старта игры, останавливается сигналом
  (именованное событие), блокировку отпускает само — убитый процесс оставлял «брошенный» мьютекс и ломал следующий запуск.
- **Одно окно меню**: новое окно сигналит старому закрыться; не ответило за 2 с (ждёт ввода текста) — закрываем по PID.
- **Один файл для передачи**: `valset.cmd` — bat-шапка `<# : ... #>` + PowerShell. Без BOM (иначе ломается bat-часть),
  PowerShell читает его явно как UTF-8.
- **C#-проверка сертификата** локального клиента кешируется в `cache\riotcert-1.dll` (компиляция ~130 мс на каждый запуск).

- **Предпросмотр**: в меню — список отличий и подтверждение; автоматика пишет без вопросов. Если наборы совпадают целиком
  (`Test-PrefsEqual`, все группы) — запись в облако пропускается. Понятным списком — только бинды общего набора и настройки
  по `settingEnum`; агентские бинды, оси и профили прицела сравниваются целиком («отличия служебные»).
- **Отложенная графика**: игра запущена → цель (PUUID или `*`) в `gfx-pending.txt`, скрытый `valset gfxwait` (мьютекс
  `Local\valset-gfxwait`) ждёт выхода + 5 с, применяет, выходит. Постоянного фона нет.
- **Наборы и код для обмена** (VALSET2: deflate + 14 бит в символ) — были в 1.0.0, убраны 2026-10-10 (см. «Узкий инструмент»).
- **Код для друга вернулся** (2026-10-25, 2.1.0, src/share.ps1 + src/app/PagesShare.cs) — под «мастер-ключ» (план п. 0).
  Формат прежний: `VALSET2:` + raw deflate(JSON {v:2, kind:full|binds, profile, xh}) по 14 бит в символ (CJK U+4E00…U+8DFF,
  в исходниках литералом нельзя — тест шрифтов консоли; регэксп собирается из [char]). 1.0.0 читает новые коды (без прицела),
  мы — его коды (графика и имя набора игнорируются; полный список прицелов → один активный).
  Что в коде: бинды (всегда, даже пустые — у друга станут как у тебя), float/int/bool/string-настройки, кроме служебных
  (`LastSeen|HasSeen|HasAccepted|HasEver|LastAccepted|ContextAware|ShootingRange|MatureContent|Mic|CustomPartyVoice|PushToTalk`),
  один прицел — активный, полем `xh` как отличия от стандартного профиля (ConvertFrom-CrosshairCode '0'). Без графики (под
  железо ПК), без имени/PUUID. Замер на моих настройках: полный 856 символов → 595 с `xh` (прицел 3366 знаков JSON → ~50);
  только бинды — 177. Ссылка с %-кодировкой — ~9 символов на иероглиф (бинды ~1500).
  Вставка: поверх текущих (списки — по settingEnum, бинды — целиком; пустой список в коде группу не стирает); прицел из кода
  — активным, такой же у аккаунта (сравнение по `xh`, порядок полей не важен) — просто выбирается, иначе первым (≤15).
  Насовсем, не «на время»: бэкап, точка отмены (account), основа сессии = записанное — чужие настройки не попадают в «мои» как
  правки из игры (на основном панель предложит «Сохранить»). При запущенной игре — отказ (не очередь). Источник кода — profile.json,
  нет его — облако текущего аккаунта. Код в буфер кладёт приложение (`do share` отдаёт поле code), «share» не стирает прошлую отмену.
  Ссылки: `valset:code/<код>` (можно без префикса VALSET2:) и `valset:pro/<ник>` → страница «preview» (`list code:…` / `list pro:…`
  — те же отличия, что запишутся; ошибка — элемент {error}, нет DPI — {error, needsDpi}). Записывает только кнопка предпросмотра;
  клик по про в списке тоже ведёт в предпросмотр.
- **Прицелы не стираются**: при «Применить всё» список прицелов аккаунта остаётся в своём порядке; эталонные, которых в нём нет,
  добавляются в начало (одноимённый другой прицел аккаунта — с пометкой «(акк)»), активный — из эталона; больше 15 — режутся прицелы
  аккаунта с конца. Итог совпал с аккаунтом — пишется строка аккаунта как есть. Проверено на основном (11 прицелов, в эталоне 1):
  изменений нет, запись не нужна.
- **Код «один прицел»**: в коде только активный профиль прицела.
- **Шкала качества**: при снимке графики незнакомое значение `*Quality` (не из проверенных) → предупреждение «проверь в игре».

- **Скины: наборы косметики** (2026-11-05, 2.1.0, src/sets.ps1 + src/loadout.ps1 + src/app/PagesSets.cs) — план п. 0, п. 2.
  Набор = скины оружия (скин, цвет, уровень), брелоки (Attachments оружия как есть), спреи и флексы (ActiveExpressions
  списком по порядку), карточка, титул, рамка уровня; уровень аккаунта, «скрыть уровень», инкогнито — из текущего.
  Надеть = свежий GET → поверх него набор → PUT целиком (лоадаут v3 без Subject/Version: Guns, ActiveExpressions,
  Identity, Incognito, DynamicOptions и любые новые поля). Перед записью —
  бэкап loadouts\backups (30 шт.) и точка отмены вида `loadout` (прежний лоадаут целиком). Чужой предмет — Riot
  отклоняет весь запрос (400/403/409/422 → «Riot не принял набор…, ничего не изменено»). Имя набора в действии панели —
  base64url (без пробелов/кавычек в командной строке запасного пути через cmd). Названия — valorant-api.com, кэш
  cache\names.json неделю на язык; нет сети — старый кэш, иначе начало ID.
  Эндпоинты (неофициальные, как у ValoVault): GET/PUT `https://pd.{shard}.a.pvp.net/personalization/v3/players/{puuid}/playerloadout`;
  выбор агента — GET `https://glz-{region}-1.{shard}.a.pvp.net/pregame/v1/players/{puuid}` (404 — не в выборе) и
  `…/pregame/v1/matches/{id}` (AllyTeam.Players[].CharacterID / CharacterSelectionState = locked). Регион/шард и версия
  клиента — из ShooterGame.log (glz-адрес, «CI server version»), иначе папка аккаунта / valorant-api.com/v1/version.
- **Лоадаут v3 вместо v2** (замер 2026-11-05, EU, release-13.09-shipping-18-5804228, только GET): v2 → 404 (панель
  падала на «Сохранить набор»: `do loadoutsave: ошибка: (404)`), v3 → 200. Форма v3: Subject, Version (929), Guns[21]
  {ID, SkinID, SkinLevelID, ChromaID, Attachments[]} — Charm* полей нет, брелоки в Attachments; ActiveExpressions[4]
  [{TypeID, AssetID}] вместо Sprays — упорядоченные слоты; TypeID `d5f120f8-ff8c-4aac-92ea-f2b5acbe9475` — спрей
  (AssetID найден в valorant-api /sprays), `03a572de-4234-31ed-d344-ababa488f981` — флекс (/flex); Identity
  {PlayerCardID, PlayerTitleID, AccountLevel, PreferredLevelBorderID, HideAccountLevel}; Incognito; DynamicOptions {}.
  Решение: брелоки — Attachments копируем как есть и сравниваем по JSON (на аккаунте замера брелоков нет, форма
  элемента неизвестна; подпись — первый ID внутри, известный справочнику, иначе «брелок»); ActiveExpressions — список
  целиком. Старые наборы (sprays): спреи по порядку в слоты-спреи текущего списка, брелоки v2 не переносятся (в
  предпросмотре — подсказка пересохранить). Кэш названий — версия 2 (флексы, уровни брелоков), старый качается заново.
  Проверено вживую: сохранение (21 оружие, 4 жеста), предпросмотр «уже надет», названия флексов/граффити.
  Автосмена (config.setsAuto, по умолчанию выкл): событие — сообщение RMS `/riot-messaging-service/v1/message/ares-pregame/pregame/v1/matches/<id>`
  по тому же WAMP (OnJsonApiEvent), что и вход/игра, без опроса; приложение зовёт `do loadoutauto`, ядро решает
  (Get-AutoSetChoice: включено, агент зафиксирован, у агента есть набор, в этом матче ещё не надевали — loadouts\auto.json)
  и надевает; «done» — по матчу больше не звать. Один набор на агента. `loadoutauto` не стирает прошлую отмену, если
  ничего не надел.
- **Повторы запросов к Riot** (2026-11-05, 2.1.0, src/cloud.ps1): было с 1.3.0 — один повтор через 1,5 с. Стало — паузы
  1-2-4-8 с (до 5 попыток), ожидание не больше 20 с (панель), не дольше срока токена (JWT exp минус 10 с); 401 или
  токен на исходе — свежий токен у клиента (Get-Session того же puuid) и продолжаем; 408/429 повторяются, прочие 4xx — нет;
  Cloudflare 403 — сразу (частые запросы могут продлить блок). Пока идут повторы — VALSET_STATUS в процессе, панель
  показывает её под «…» (таймер 0,7 с только пока Busy). Запасной путь через cmd — только журнал.
- **Ctrl+Alt+V в игре ничего не открывает**: ярлык «Пуска» запускает `valset-open-1.exe` (C#, 4 КБ, без окна) —
  если на переднем плане окно VALORANT-Win64-Shipping, выходит; иначе открывает valset.cmd. Проверять в самом меню
  поздно: окно консоли уже появилось бы и отобрало фокус у полноэкранной игры. Не собрался exe — ярлык ведёт на cmd.
  Вне игры проверено (меню открывается); в игре — не проверено вживую.
- **«Все скины»** (2026-11-05, 2.1.0, src/skins.ps1, PagesSkins.cs, Img.cs). Владения — один GET
  `https://pd.{shard}.a.pvp.net/store/v1/entitlements/{puuid}` (без типа — все типы сразу, EntitlementsByTypes[]); по типу
  `/{ItemTypeID}` тоже работает. ID типов сверены вживую (EU, только GET): уровни скинов e7c63390… (70), цвета 3ad1b2b2…
  (42), брелоки dd3bf334… (191 экземпляр, ItemID — uuid уровня брелока + InstanceID), спреи d5f120f8… (91), карточки
  3f296c07… (153), титулы de7caa6b… (93), флексы 03a572de… (5); ещё 01bb38e1… (24) и f85cb6f7… (1) — не используем.
  Скин свой, если есть хоть один его уровень; стандартный скин (weapon.defaultSkinUuid) — всегда; базовый цвет — у
  каждого своего скина. Запись — тот же PUT v3, что у наборов (Write-LoadoutChange в sets.ps1: точка отмены, бэкап);
  спецификация предмета — только GUID и числа (`gun:<оружие>:<скин>:<уровень>:<цвет>`, `expr:<слот>:<тип>:<id>`,
  `card:`, `title:`). Брелоки — только просмотр: в лоадауте замера Attachments пустые, форму элемента v3 не видели.
  Каталог — valorant-api.com на языке интерфейса, cache\catalog-<язык>.json (~1,7 МБ). Обновление по версии игры, не по
  таймеру: версия из ShooterGame.log («CI server version») = версии каталога → сеть не нужна; иначе GET /v1/version
  (riotClientVersion) — новее → скачать; valorant-api ещё не обновился → старый каталог, повторно не спрашиваем до смены
  версии игры. В памяти каталог не держим (только при открытии страницы). Картинки — Img.cs: место под картинку → в
  очередь, только когда видно в прокрутке (±120 px), один фоновый поток, файл на диск cache\img (только
  https://media.valorant-api.com/), в память — уменьшенная копия (DecodePixelWidth ≈ ширина × 1,5), память чистится
  при закрытии панели. Кэш картинок на диске не чистится (десятки КБ на файл).
  Попутно: проверка сертификата в приложении отвергала все внешние адреса (принимала только 127.0.0.1) — теперь обычная
  проверка + исключение для 127.0.0.1; TLS 1.2 включён явно (exe без TargetFramework).
- **Кнопка поверх игры** (2026-11-05, 2.1.0, Overlay.cs). Меняет прежнее «поверх игры — нет» (значок у клиента) — по
  просьбе владельца, но без внедрения: своё окно WS_EX_TOPMOST|WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW, игру не трогаем
  (только читаем режим экрана из GameUserSettings.ini). Видна, если окно VALORANT-Win64-Shipping на переднем плане
  (SetWinEventHook EVENT_SYSTEM_FOREGROUND, ставится только пока игра запущена) и игрок в меню: своё присутствие в
  чате Riot — событие `/chat/v4/presences` по тому же WAMP, поле private (base64 JSON) →
  matchPresenceData.sessionLoopState = MENUS / PREGAME / INGAME (замер 2026-11-05: MENUS; ключи объекта по алфавиту,
  private перед puuid); свой puuid — GET /chat/v1/session. В выборе агента и в матче — скрыта. Опроса нет: присутствие
  читается GET-ом один раз при запуске игры/подключении, дальше события. Место — слева по центру окна игры. Клик —
  панель (обычное окно с фокусом) на «Все скины».
  **Режим «Полноэкранный» (FullscreenMode 0, у владельца)**: решено кнопку не показывать. Окно поверх без фокуса игру

## Раздача (1.0.0, 2026-10-06)

- Релиз: `build.ps1` → `dist\VALSET-<версия>.zip` (valset.cmd + README.txt + LICENSE, имена латиницей — встроенный
  распаковщик Windows может исказить кириллицу) и `dist\SHA256SUMS.txt`. Версия — строка `$Version` в src\valset.ps1.
- Скачанный файл при запуске сам предлагает установку / обновление (сравнивает `$Version` установленного valset.cmd).
- Первый запуск (нет своих настроек и истории): приветствие и три шага. Помощник в фоне — только по выбору.
- Лицензия MIT + отказ: не связан с Riot Games. В README — честный раздел о безопасности и рисках.
- «История моих настроек»: версия перед каждым изменением («Запомнить как мои»), последние 10;
  `profile.json.bak` больше не пишется. «Запомнить» не с основного аккаунта — предупреждение.
- Графика на ПК с несколькими аккаунтами: один раз спросить «во все или только в текущий» (config.json → gfxAll),
  в фоне без ответа — только в текущий. Переключатель — «Аккаунты» → «Графика на этом ПК».
- После установки — запасные пути: ярлык «VALSET» в Пуске, команда valset (хоткей иногда — после перезахода).
- Не exe: обёртка .exe не убирает консоль, а неподписанный exe, запускающий PowerShell, антивирусы ловят чаще,
  чем читаемый .cmd. Окно с кнопками — отдельная переделка, если программа приживётся.
- Путь нового пользователя проверен: архив распакован в чистую папку, valset.cmd запускается (status).

- **Установка одной командой** (`install.ps1` в корне, через Win+R): скачивает valset.cmd из последнего релиза,
  сверяет SHA-256 с SHA256SUMS.txt, ставит, открывает меню. Скачанное PowerShell'ом не помечается «из интернета» —
  нет SmartScreen. `install.ps1` — **без BOM**: при `irm | iex` BOM попадает в текст и ломает команду (проверено).
  TLS 1.2 явно (старые Win10), `-UseBasicParsing` (в Win11 нет IE). Тест проверяет отсутствие BOM и разбор.

- **Два языка** (2026-10-06): каждая строка интерфейса — пара `(L 'рус' 'eng')` прямо в коде (перевод не разъезжается
  с логикой). Язык: VALSET_LANG → config.json `lang` → русский, если в языках/раскладках Windows есть ru/uk/be/kk,
  иначе английский. Переключение — L в справке и на приветствии. valset.log — по-русски (служебный). Тесты — на
  русском (VALSET_LANG=ru) + отдельная проверка `status` по-английски. Установщик install.ps1 выбирает язык так же.
- **Подача для англоязычной аудитории**: иметь несколько своих аккаунтов Riot разрешает, передавать аккаунт другому —
  нарушение правил. Поэтому в описаниях — «твои аккаунты» (второй регион, второй аккаунт, переустановка, новый ПК),
  без «смурфов» и «аккаунта друга»; код настроек — чтобы импортировать в **свой** VALSET.

- **«На время» — стандарт** (2026-10-06): реальный сценарий — играть со своими настройками на аккаунтах друзей
  и оставлять им их собственные. Любой перенос, кроме основного и помеченных «мой» (accounts.json → own), — на время.
  Исходные — temp\<puuid>.json (не чистится вместе с бэкапами, повторный перенос не затирает). Вернуть можно,
  только пока ты в аккаунте (после выхода записи в его облако нет); клиент после игры обычно не закрывают —
  помощник возвращает через 3 с после события Delete external-sessions. Не успели — «анлак»: исходные ждут
  следующей игры на этом аккаунте или ручного «Вернуть исходные». Помощник для этого — с согласия, спрашивается
  один раз (config.json → tempAuto). Графику не возвращаем: она локальная. Не проверено вживую на втором аккаунте.
- **3 с после закрытия игры, а не 20**: событие Delete external-sessions приходит, когда процесс игры уже
  завершён — дописывать ей нечем; 20 с были запасом «на всякий случай», а для возврата исходных важна скорость.
- **Типографские кавычки “ ”** PowerShell считает обычными: внутри строки "…" они её обрывают без ошибки разбора
  (сломалось бы в английском режиме). Внутри "…" — только с обратной кавычкой: `“ `”. Тест ловит разбором.

## Совместимость Windows 10 / 11 (проверено 2026-10-06 на Win11, для Win10 — по составу системы)

- Всё встроено в обе системы: PowerShell 5.1, .NET Framework 4.x (ClientWebSocket — Win8+), компилятор C# для
  сторожа (Add-Type, C# 5), уведомления WinRT (Win10 1607+), FileSystemWatcher, HKCU Run, ярлык «Пуска» с хоткеем.
- **Шрифты**: Win10 открывает меню в старой консоли (Consolas / Lucida Console) без подстановки шрифтов —
  ◆ ⚠ ✓ ✔ ✖ там квадратики. Заменены на ♦ ‼ √ ×, ● → •. Тест проверяет каждый символ src\ по обоим шрифтам.
- **Высота окна**: старая консоль — 30 строк; при высоте < 34 шапка однострочная, главное меню ≤ 28 строк.
- **Путь с кириллицей и пробелами** (`тест папка Имя`): собранный valset.cmd запускается, данные пишутся.
- Синтаксис PowerShell 7 исключён: build.ps1 разбирает сборку парсером 5.1.
- Не проверить здесь: антивирусы кроме Defender (сторож — свежесобранный exe без подписи), корпоративные
  ограничения (AppLocker / Constrained Language Mode запрещают Add-Type — тогда не будет только помощника).
